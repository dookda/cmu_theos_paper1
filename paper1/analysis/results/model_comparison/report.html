ข้อค้นพบหลัก

1 · Class weights + augmentation และ NIR ยังไม่เพิ่ม mIoU รวม — ยืนยันแล้วบน test set

Baseline ชนะทั้ง 6 โมเดลบน val และยืนยันซ้ำบน test set ที่ไม่เคยแตะ (54.66 เท่า val เป๊ะ) — val/test splits ตรวจแล้วว่า identical ทั้ง 3 data roots จึงเทียบกันได้จริง

1.5 · ต้นตอน่าจะอยู่ที่ label ไม่ใช่โมเดล

Confusion matrix ชี้ว่าดินโล่ง 24–42% และทุ่งหญ้า ~30% ถูกทายเป็น "พื้นหลัง" ซึ่งเป็นคลาสครอบจักรวาลที่กิน 26.5% ของพิกเซล — ถ้าใน background มีดินโล่ง/หญ้าจริงที่ไม่ได้ label การเทรนต่อกี่รอบก็ติดเพดานนี้ ควร audit label ก่อนทดลองใหญ่ครั้งถัดไป

2 · คอขวดอยู่ที่ 4 คลาสหายาก ไม่ใช่สถาปัตยกรรม

ดินโล่ง (~27) ทุ่งหญ้า (~31) พื้นหลัง (~39) ถนน (~44) ต่ำกว่ากลุ่มคลาสหลัก (67–78) มากกว่า 30 จุด ขณะที่โมเดลทั้ง 6 ตัวต่างกันเองแค่ ~2 จุด — ลงทุนกับข้อมูล/loss ของคลาสอ่อนคุ้มกว่าเปลี่ยนโมเดล

3 · NIR ช่วยเฉพาะทาง: ถนน +1.1 ทุ่งหญ้า +0.6 แต่ฉุดดินโล่ง −2.7 น้ำ −1.2

สอดคล้องกับฟิสิกส์: NIR แยกพืชพรรณ/สิ่งปลูกสร้างได้ดี แต่ raw NIR เพิ่ม noise ให้ดินโล่ง — บ่งชี้ว่า NDVI/NDWI (index ที่ normalize แล้ว) น่าจะได้ผลกว่าใส่ NIR ดิบ

4 · HRNet-W48 เสถียรที่สุด · UNet++ ทำ peak สูงสุด

HRNet นำใน weighted (54.41) และ NIR (53.95) และตามหลัง peak ของ baseline แค่ 0.03 — เป็นแกนที่ดีสำหรับ ensemble ร่วมกับ UNet++ และ UNet-EfficientNet

การทดลองถัดไปที่แนะนำ (เรียงตามความคุ้มค่า)

  1. ยืนยัน validation protocol — เสร็จแล้ว: val/test identical ทั้ง 3 roots
  2. Confusion matrix ของคลาสอ่อน — เสร็จแล้ว: คลาสอ่อนรั่วไป background เป็นหลัก
  3. Audit label บริเวณ background — สุ่มดู val tiles ที่โมเดลทาย "ดินโล่ง/หญ้า" แต่ label บอก "background" ว่าใครถูกกันแน่ ถ้า label ผิดเยอะ → แก้ label แล้วเทรนใหม่คุ้มกว่าทุกเทคนิค
  4. Ensemble HRNet + UNet++ + UNet-EfficientNet — เฉลี่ย softmax ก่อน argmax ใช้ checkpoints ที่มีอยู่แล้ว คาดหวัง +1–3 จุดโดยไม่ต้องเทรน
  5. Dice + Focal loss แทน weighted CE — Dice optimize IoU ของคลาสหายากตรงกว่า pixel-weighted CE ที่ผลออกมาแล้วว่าไม่ช่วย
  6. NDVI + NDWI เป็น channel 5–6 — NIR ดิบเพิ่ม recall ดินโล่งแต่ precision ตก index ที่ normalize แล้วน่าจะเสถียรกว่า
